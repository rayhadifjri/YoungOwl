1Yang Anda butuhkan

  • Sebuah VPS (Ubuntu 22.04 atau 24.04), minimal 2 GB RAM. Idealnya VPS terpisah khusus lab.
  • Akses SSH ke VPS (alamat IP, user, dan password atau kunci SSH dari penyedia).
  • Komputer Anda dengan terminal (Linux/macOS, atau PowerShell/PuTTY di Windows).
  • Opsional: sebuah domain yang mengarah ke IP VPS, kalau mau pakai HTTPS (Langkah 9).
Keamanan. Aplikasi inti (database, akun) tidak pernah dibuka ke internet. Hanya salinan lab yang publik, dan itu terisolasi serta tidak bisa keluar ke internet. Detail di docs/lab-mode.md.

2Masuk ke VPS & buat user

Dari terminal komputer Anda, masuk ke VPS (ganti IP_VPS dengan IP Anda):

ssh root@IP_VPS

Buat user biasa dengan hak sudo (jangan bekerja sebagai root sehari-hari):

adduser owl
usermod -aG sudo owl
su - owl        # pindah ke user baru

3Pasang Docker

Young Owl berjalan dengan Docker, jadi Anda tidak perlu memasang Node, PostgreSQL, dll satu per satu.

curl -fsSL https://get.docker.com | sh
sudo usermod -aG docker $USER

Keluar lalu masuk lagi (exit kemudian ssh owl@IP_VPS) supaya hak Docker aktif. Cek: 

docker --version
docker compose version
Berhasil bila kedua perintah menampilkan nomor versi.

4Ambil kode Young Owl

git clone https://github.com/rayhadifjri/YoungOwl.git
cd YoungOwl
Catatan. Pastikan fitur terbaru (lab mode, dll) sudah ada di cabang main. Kalau PR-nya belum digabung, beri tahu Claude untuk menggabungkannya dulu, atau checkout cabang yang sesuai sebelum lanjut.

5Atur rahasia di file .env

Salin contohnya lalu sunting:

cp .env.example .env
nano .env

Ganti nilai berikut dengan yang kuat dan unik:

KunciIsi dengan
POSTGRES_PASSWORDPassword database yang panjang & acak
REDIS_PASSWORDPassword Redis yang kuat
SEED_ADMIN_PASSWORDPassword login admin Anda
SEED_RESEARCHER_PASSWORDPassword akun researcher
SEED_STUDENT_PASSWORDPassword akun student
SEED_ON_STARTtrue untuk start pertama saja (memuat data dummy)

Butuh nilai acak yang kuat? Hasilkan cepat:

openssl rand -base64 24

Simpan file di nano dengan Ctrl+O, Enter, lalu keluar Ctrl+X.

Penting. Setelah start pertama berhasil, ubah lagi SEED_ON_START menjadi false. Kalau dibiarkan true, data akan dimuat ulang (menghapus perubahan) setiap kali stack dinyalakan.

6Jalankan (deploy)

Satu perintah menyalakan aplikasi inti (postgres, redis, api, web):

bash infrastructure/deploy/deploy.sh

Build pertama memakan beberapa menit. Setelah selesai, cek semua kontainer berjalan: 

docker compose ps
Berhasil bila layanan web dan api berstatus running, dan web mendengar di 127.0.0.1:3000 (hanya lokal — itu memang disengaja).

7Buka aplikasi lewat SSH tunnel

Karena aplikasi sengaja tidak dibuka ke internet (sampai HTTPS siap), akses dari laptop Anda lewat terowongan SSH. Jalankan ini di komputer Anda, bukan di VPS: 

ssh -L 3000:localhost:3000 owl@IP_VPS

Biarkan jendela itu terbuka, lalu buka peramban ke http://localhost:3000. Masuk dengan admin@youngowl.lab dan SEED_ADMIN_PASSWORD yang Anda set.

Berhasil bila Anda melihat dashboard Young Owl dengan data dummy.

8Pasang lab yang bisa diserang dari Kali

Kalau Anda juga ingin salinan rentan untuk latihan dari Kali, nyalakan dengan:

bash infrastructure/deploy/deploy.sh --with-lab
sudo bash infrastructure/lab/firewall.sh

Lab terbuka di port 8080. Dari Kali, targetnya http://IP_VPS:8080. Buka port itu di firewall penyedia/ufw bila perlu: 

sudo ufw allow 8080/tcp
Sadari risikonya. Port 8080 publik berarti siapa pun di internet bisa menjangkau lab. Itu memang tujuannya, dan lab sudah diisolasi (data dummy, tanpa jalan keluar, reset otomatis). Jangan pernah memasang VULN_MODE pada salinan aplikasi inti Anda.

Panduan serangannya ada di ebook Panduan Pentest Lab Sendiri.

9HTTPS dengan Nginx (opsional, disarankan)

Untuk mengakses dashboard lewat domain dengan HTTPS, pasang Nginx dan sertifikat gratis:

sudo apt update && sudo apt install -y nginx certbot python3-certbot-nginx

Buat konfigurasi situs (ganti domain Anda):

sudo nano /etc/nginx/sites-available/youngowl
server {
    server_name youngowl.contoh.com;
    location / {
        proxy_pass http://127.0.0.1:3000;
        proxy_set_header Host $host;
        proxy_set_header X-Forwarded-For $remote_addr;
        proxy_set_header X-Forwarded-Proto $scheme;
    }
}
sudo ln -s /etc/nginx/sites-available/youngowl /etc/nginx/sites-enabled/
sudo nginx -t && sudo systemctl reload nginx
sudo certbot --nginx -d youngowl.contoh.com

Lalu set COOKIE_SECURE=true di .env dan jalankan ulang deploy.sh. Buka hanya port yang perlu: 

sudo ufw allow OpenSSH
sudo ufw allow 'Nginx Full'
sudo ufw enable

10Reset otomatis & update

Reset lab berkala

Agar lab kembali bersih setiap beberapa jam, tambahkan cron:

crontab -e
0 */6 * * * cd /home/owl/YoungOwl && bash infrastructure/lab/reset.sh >> /var/log/youngowl-lab-reset.log 2>&1

Update ke versi terbaru

cd ~/YoungOwl
git pull
bash infrastructure/deploy/deploy.sh --with-lab

11Kalau ada masalah

GejalaCoba ini
Lupa/ingin lihat log kontainer docker compose logs -f web atau api
Perubahan .env tidak terpakai Jalankan ulang bash infrastructure/deploy/deploy.sh
Port 3000 tidak bisa dibuka dari laptop Pastikan terowongan SSH (Langkah 7) masih berjalan
Lab tidak bisa dijangkau dari Kali Buka port 8080 di ufw dan firewall penyedia VPS
Database penuh / ingin mulai bersih docker compose down -v lalu set SEED_ON_START=true sekali
Butuh berhenti sementara docker compose stop (data tetap), start untuk lanjut
Bantuan lebih lanjut. Dokumen rinci ada di repo: docs/deploy-vps.md dan docs/lab-mode.md. Catatan: sesi Claude di cloud tidak bisa SSH ke VPS Anda, jadi perintah di atas Anda jalankan sendiri. Bila komputer Anda terhubung ke thread dan bisa menjangkau VPS, Claude bisa menjalankannya bersama Anda.
